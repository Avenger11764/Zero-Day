01The gap

A detector that only sees one conversation at a time

The baseline autoencoder scores each network flow independently: a 76-number vector describing a single conversation — packet counts, durations, flag counts. It learned what normal looks like and flags what doesn't fit. It works.

But reducing traffic to independent per-flow rows throws away three things: who sent it, who received it, and what else those hosts were doing at the same time.

What M5a can see

A 4 GB transfer. Impossible TCP flag combinations. A connection to a port that appears nowhere in training. All of it lives inside the flow's own numbers.

What it cannot

One host opening short, well-formed connections to 200 machines. Every single flow is ordinary. The attack exists only in the relationship between flows.

This is not a training problem. Give M5a a perfect model and infinite data and it still misses — the evidence was destroyed at feature-extraction time.

02The insight

“One host contacted 200 peers” is just out-degree

That sentence cannot be written into a single 76-dimensional row, because the row describes one conversation. But it is trivially readable as a property of a node in a graph.

Change the data structure and a whole class of attack stops being a subtle statistical anomaly and becomes a number you read straight off the node.

flows                          graph
┌──────────────────┐           192.168.1.66
│ flow  1 ... 76d  │          ╱ │ │ │ ╲        out_degree = 200
│ flow  2 ... 76d  │    ●   ●   ●   ●   ●   ●   median   = 2
│ ...              │
│ flow 200 ... 76d │   every flow individually normal
└──────────────────┘   the fan-out is the attack

That reframing is the entire justification for the second detector — not that graph neural networks are fashionable.

03Blocker

None of our datasets could form a graph

Before any modelling, the data had to be checked. All three failed, each differently — and the failures were silent.

DatasetFailure modeVerdict
CICIDS2017 MachineLearningCVE 79 columns, no IP columns at allunusable
dataset_10k_normal.csv 508 clients, all touching the identical 2 servicescollapses
live_capture.csv 12,503 unique services across 12,504 flowsdegenerate

The second one matters most, and it is subtle. A GNN builds each node's representation by aggregating its neighbours. If every client has the same neighbour set, every embedding collapses to the same vector — the model would have trained happily and learned nothing.

The existing temporal model's per-host grouping had been silently dead for the same reason: its 'Source IP' in df.columns guard was always false, so it chunked flows in file order instead. Fixed, and graph_health() now detects collapse before a wasted run.

04Built

Graph construction, and the decisions behind it

Flows become one host-communication graph per time window.

Nodes
hosts
8 features. Out-degree literally counts scan targets.
Edges
directed
One-to-many (scan) and many-to-one (DDoS) must not collapse together.
Windows
60s
Time-based, not fixed-count — “200 peers in a minute” is a rate.
  • Autoencoder, not classifier. A classifier only recognises families present in its labels — which defeats the entire zero-day premise. It would also break the ablation: M5a scores a reconstruction distance, so scoring M5b as a probability leaves no shared threshold and no comparable ROC.
  • SAGEConv over GCNConv. GCN's symmetric normalisation washes out exactly the degree signal we are trying to detect.
  • Edge-level alerting. The frozen ScoredAlert schema requires both source and destination, so an edge maps onto an alert cleanly; a node does not.
05Fusion

Two halves that had never been connected

The specification defines this detector as graph structure + sequence. The project had both halves as separate files that never spoke to each other. Two disconnected models is not a graph-temporal model.

window₁ ──▶ graph ──▶ GNN ──▶ embedding ┐
window₂ ──▶ graph ──▶ GNN ──▶ embedding ├──▶ LSTM ──▶ reconstruct
window₃ ──▶ graph ──▶ GNN ──▶ embedding ┤          features
window₄ ──▶ graph ──▶ GNN ──▶ embedding ┘              │
                                                     reconstruction
   structure, per window        change over time    error = score

A single window cannot distinguish a backup server that always fans out to 200 machines at 02:00 from a laptop that never has and just started. Both are the same graph. Only the sequence separates a stable pattern from a change — which is precisely the slow, gradual attacker the red-team harness simulates.

07Ablation

Does the complex model actually earn its place?

A controlled comparison changes exactly one variable: the data structure. Same flows, same benign-only training, same reconstruction-error scoring.

The test scan is built from real benign flows with every feature value left untouched — only the source and destination are re-attributed. So the baseline must score them benign. That is the point, not a rigged test.

M5a · per-flow
MISSED
Flags the scan at 2.5% versus a 1.0% false-positive floor on benign traffic — a +1.5pp lift, i.e. noise.
M5b · relational
RANK 1
Attacker is the single most anomalous host of 710, scoring 532× the median.

The verdict compares against the false-positive floor, not zero. At a 99th-percentile threshold ~1% of benign traffic flags by construction — counting that as detection would be counting the model's own noise.

08Limits

Where this is weak — said before you ask

  • High AUC does not mean good alerts. Patator scores 0.9913 AUC with zero true positives in the top 100, because 184 benign host-windows outrank the first attacker. AUC measures average ranking across the whole set; an analyst only ever sees the top of the queue. P@100 is the honest operational metric, and it is zero on two of seven families.
  • The port-scan win is aggregation, not topology. CICIDS2017's PortScan is vertical — one attacker, one victim, 1000 ports — so out-degree is 1 and does not fire (0.72× separation). What separates the classes is unique_dst_ports at 199×. The defensible claim is “per-flow features destroyed the evidence, per-host structure recovered it,” not “the graph topology caught it.” DDoS is the family that genuinely exercises topology, and out-degree does fire there.
  • The fused model needs history. A host must appear in five consecutive windows to produce a sequence, so single-burst attackers are invisible to it — the graph-only model catches those instead. The two are genuinely complementary, which is the strongest argument for the ensembler.
  • Evaluation is capped at 150k rows per file pending a longer run on larger hardware.
